# FailureLens v0.3 計画書

作成日: 2026-11-07 / 状態: 計画(結果はまだありません)
前の版の結果: [v0.2 レポート](../v0.2/REPORT.md)(不採用)

## なぜ作るのか(やさしい説明)

v0.2 でわかった問題は2つです。

1. **評価が公平でなかった**: 最終評価データのエラーログに、実在しないファイル名が書かれていました。そのため、現行の baseline が候補を見つけられず、「新モデルが baseline より良いか」を測れませんでした。
2. **学習の例が簡単すぎた**: 「1行だけ壊す」例は、単語の一致だけでも解けます。モデルを使う意味が出る、難しい例が足りません。

v0.3 では、この2つを直します。

## 作ること

| 段階 | 内容 |
|------|------|
| 1 | **新しい最終評価データ(Gate C v2)**: 学習・開発用・旧最終評価のどれとも重ならない、権利確認済みのリポジトリで作る。エラーログのパスが実在し、baseline も公平に動く形にする |
| 2 | **難しい例を増やした学習データ**: 複数行の変更、原因と症状の場所が離れた失敗、語彙の手がかりが少ない例を追加する |
| 3 | 複数の候補を学習し、開発用データで1つ選ぶ(選ぶルールは学習の前に固定) |
| 4 | 選んだ候補を新しい最終評価データで1回だけ測り、合格ラインで採否を判定 |
| 5 | `REPORT.md` を作成し、MLflow に全版を記録 |

## 合格ライン(変更しない)

v0.2 と同じ、2026-10-29 に凍結済みの Gate B 基準です。

- 関数 Top-1 が 0.4 以上、MRR が 0.6 以上
- baseline からの改善が Top-1 で +0.4 以上、MRR で +0.1 以上(同梱の baseline との同条件比較)
- 30件以上、3リポジトリ以上
- 推論 p95 が 5 秒以下、メモリが 8 GiB 以下、10億パラメータ以下

判定ルール:
- 新しい最終評価データは、**どの候補についても、選んだ1候補につき1回だけ**使います。旧最終評価データ(v0.2 で結果を見たもの)は、選択に使いません。
- 全部満たしても、公開・配布は人間のオーナーの判断です。満たさなければ不採用で、公開しません。

## 守ること

- データの中身(ケース、ラベル、ソース、ケース別結果)は Git にも報告書にも載せません。
- 外部リポジトリのテスト実行は、ネットワークを切った Docker の中だけで行います。
- 学習・評価の結果は MLflow に記録します。Discord への通知は使いません(ローカルの記録のみ)。
- 不採用の版は公開しません。
