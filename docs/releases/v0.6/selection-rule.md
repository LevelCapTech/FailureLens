# v0.6 候補の選び方(結果を見る前に固定)

作成日: 2026-11-09 / 状態: **固定済み(実験前)**。計画は [PLAN.md](PLAN.md)。
ここに書いたことは、点数を見た後に変えません。追加の候補も作りません。

## データ

| 用途 | データ | 件数 |
|------|--------|------|
| 学習 | v0.3 の学習用データ(`train`)。全部を学習に使う | 351件、10リポジトリ |
| 学習内の検証 | 上と同じデータで、リポジトリを1つ抜く交差検証(10通り) | 同上 |
| 候補の選択 | v0.3 の開発用データ(`dev`)。学習には使わない | 98件、4リポジトリ |

- 候補の範囲は v0.4 と同じ「失敗状態のソースの全関数(リポジトリ全体)」。学習用データのケースごとの失敗状態のソースは、既存の記録(変更の内容)から、開発用データと同じ手順で作る。
- 正解の関数は、変更した関数。ケース別の結果は出力せず、集計だけを保存する。

## 手がかり(特徴量。各候補の関数ごとに計算)

構造・語彙の特徴(グループ G1)。すべて決定的(乱数なし)で、v0.4 の評価コードと同じ解析器とグラフ作りを使う。

| 記号 | 内容 |
|------|------|
| f01 | スタック得点(v0.4 の s: 深さと最深フレーム) |
| f02 | スタックに出る関数か(0/1) |
| f03 | 最も内側(最深)のフレームの関数か(0/1) |
| f04 | 最深フレームからの相対的な位置(最深が0、外側ほど1に近い。スタックに出ない関数は1) |
| f05 | スタックの関数に直接呼ばれているか(呼び出し1歩、呼ばれる側) |
| f06 | スタックの関数を直接呼んでいるか(呼び出し1歩、呼ぶ側) |
| f07 | 呼び出しで2歩離れているか(1歩ではなく2歩、向きは問わない) |
| f08 | スタックの関数までの最短の距離(上限3。スタックの関数は0、届かなければ3) |
| f09 | 2歩以内にあるスタックの関数の数(log(1+数)) |
| f10 | BM25 の得点を最大値で割った値 |
| f11 | BM25 の順位の逆数 1/(1+順位) |
| f12 | 現行 baseline の語彙得点(ログの語が含まれる数、上限3、÷3) |
| f13 | log(1+BM25 の生の得点) |
| f14 | 関数名の単語のうち、エラーログにも出る単語の割合 |
| f15 | 関数名がエラーログの文字列にそのまま出るか(語境界、0/1) |
| f16 | スタックの関数と同じファイルにあるか(0/1) |
| f17 | ログのフレームのファイルと同じディレクトリにあるか(0/1) |
| f18 | ファイルパスの単語のうち、エラーログにも出る単語の割合 |
| f19 | 関数の中に、ログの例外の種類の名前が出るか(0/1) |
| f20 | log(1+関数の行数) |
| f21 | log(1+関数の単語数) |
| f22 | log(1+そのケースの候補数) |
| f23 | そのケースでスタックの関数を1つでも見つけられたか(0/1) |

任意の特徴(グループ G2、AI モデルの類似度)。

| 記号 | 内容 |
|------|------|
| g01 | v0.2 候補 b の埋め込みでのコサイン類似度を、そのケース内で0〜1に正規化した値 |
| g02 | 同じ類似度の順位の逆数 1/(1+順位) |

G2 は v0.2 候補 b の1種類だけ(v0.4 の測定で、モデル単独の順位付けは弱かったため、他のモデルは試さない)。

## 学習のしかた(固定)

- 候補の範囲は数千の関数になるので、学習では次の部分集合を使う: 各ケースの正解の関数、スタックまたは呼び出し2歩以内の関数すべて、BM25 の上位100件、ほかから無作為に100件(乱数は `20261106 + ケース番号`)。順位付け(評価)のときは全候補を使う。
- 特徴量は学習データの平均と標準偏差で標準化する(線形モデルのみ)。
- ハイパーパラメータは下表のとおり固定し、調整しない。

## 候補(6種、これだけ)

| 記号 | 手法 | 特徴 | 設定 |
|------|------|------|------|
| A | ロジスティック回帰(個々の候補が正解か) | G1 | L2 正則化 C=1.0、最大2000回 |
| B | ロジスティック回帰 | G1 | C=0.1 |
| C | 順位学習の線形モデル(正解と不正解の特徴の差から、正解を上にする) | G1 | ロジスティックの二値分類、C=1.0、切片なし |
| D | 小さな決定木の集まり(勾配ブースティング、scikit-learn の HistGradientBoosting) | G1 | 深さ3、葉8、学習率0.05、200本、L2=1.0、乱数0、早期停止なし |
| E | D と同じ | G1+G2 | 同上 |
| F | A と同じ | G1+G2 | C=1.0 |

## 選び方

1. 6種を、開発用データ(98件)での関数 MRR が高い順に並べ、最も高いものを「最良の候補」とする。同点は関数 Top-1、それも同点なら G2 を使わない方、それも同点なら記号の昇順。
2. 最良の候補が、次の**すべて**を満たすときだけ「合格」とする。1つでも外れたら「不合格(この方向は止める)」。

| # | 基準 | 内容 |
|---|------|------|
| R1 | 改善幅 | 関数 MRR が V5 より **+0.03 以上**高く、対応のあるリポジトリ層別ブートストラップ(10,000回、乱数 20261030)の差の95%区間の**下限が0より大きい** |
| R2 | 後退しない | 開発用データの4リポジトリのどれでも、MRR が V5 より 0.05 を超えて低くならない |
| R3 | 選び方の偏りの確認 | 開発用データのリポジトリを1つ除いて(残り3つで6種から選び)、除いた1つで測る。これを4回行い、全体の MRR が V5 より **+0.03 以上**高い |
| R4 | 学習データ内の確認 | 学習データ内の一つ抜き交差検証(10通り)の関数 MRR が、V5 を同じ範囲で測った値より高い(差の点推定が0より大きい) |
| R5 | 速さと軽さ | 索引づけと特徴量の計算を含めた、ケースごとの処理時間の p95 が 5 秒以下、最大メモリが 8 GiB 以下(CPU)。G2 を使う候補は、埋め込みを計算する分(キャッシュなしの代表値)も含める |

## 補助の報告(判定には使わない)

- G1 と G1+G2 の最良を比べ、AI モデルの類似度が役に立つかを報告する。
- 特徴量の重み(線形モデル)と、グループを抜いたときの MRR の変化(決定木)。
- V5、S0、L1、6種すべての開発用データでの Top-1 と MRR、V5 との差と95%区間、リポジトリ別の MRR。
- 候補の範囲に正解が含まれる割合。

## 凍結と最終評価の約束(後の担当者へ)

- 合格した場合は、選んだ候補の学習済みファイル(ローカルのみ、ハッシュを記録)と、最終評価の正確なコマンドを `final-command.md` に残して終わる。この担当は最終評価を実行しない。
- 最終評価は、新しい最終評価データ(Gate C v3)で、凍結した候補を**1回だけ**測る。比較は V5、S0(旧方式)、L1(語彙・全体)。
- 合格ラインは Gate B の凍結基準を字義どおり当てはめる: 関数 Top-1 0.4 以上、MRR 0.6 以上、S0 と L1 のそれぞれに対して Top-1 +0.4 以上・MRR +0.1 以上、30件以上、3リポジトリ以上、p95 5秒以下、メモリ 8 GiB 以下、10億パラメータ以下。V5 との差も併せて報告する。
- 開発用データでの選択による偏りがあること、最終評価データの上限(候補の範囲に正解がある割合)があることを、レポートに書く。
- 凍結した学習済みファイルは、ハッシュを確認してから読み込む(信頼できないファイルは読み込まない)。
