# FailureLens v0.6 計画書

作成日: 2026-11-09 / 状態: **計画(結果はまだありません)**
前の版: [v0.5 レポート](../v0.5/REPORT.md)(呼び出し関係を使う baseline を標準にした)

## このバージョンで何をするのか(やさしい説明)

v0.5 で、AI モデルを使わなくても、次の2つの手がかりだけで順位が良くなることがわかりました。

1. エラーが起きた経路(スタックトレース)に出てくる関数
2. その関数と「呼ぶ・呼ばれる」関係にある関数

ただし、この2つの手がかりをどれくらい重く見るかは、人間が決めた固定の数字(0.25 と 0.25)でした。v0.6 では、これを**小さな学習(機械学習)で自動的に決められるか**を試します。

使う手がかりは、v0.5 の2つに加えて、次のようなものです。

- エラーログの単語と関数の一致のしかた
- 関数の名前やファイルの場所がログと似ているか
- 呼び出し関係の「向き」(呼んでいるのか、呼ばれているのか)と距離
- 関数の大きさ
- (任意)これまでに作った AI モデルの「似ている度合い」。入れた場合と入れない場合を比べて、役に立つかを確かめます

学習の道具は、**小さくて中身が説明できるもの**(ロジスティック回帰、順位学習の線形モデル、小さな決定木の集まり)に限ります。大きな AI モデルの追加学習は、この版では行いません。ライブラリ本体の依存も増やしません(実験用の環境でだけ使います)。

## 何をどう確かめるか

| 段階 | 内容 |
|------|------|
| 1 | この計画と「選び方の約束」をコミットして固定する(結果を見る前) |
| 2 | 実験用のコードを作ってテストする |
| 3 | v0.3 の**学習用データ**(351件)で候補6種を学習する。学習用データの中でも、リポジトリを1つ抜く検証(一つ抜き交差検証)をして過学習を確認する |
| 4 | v0.3 の**開発用データ**(98件)で6種を比べ、約束どおり1つ選ぶ |
| 5 | 基準を満たせば、選んだ1つを「凍結」(ファイルとハッシュを残す)して終了。満たさなければ「この方向は止める」とレポートに書いて終了 |
| 6 | 凍結した候補の最終評価は、**別の担当が新しい最終評価データ(Gate C v3)で1回だけ**行う。この計画では実施しない |

## 合格の考え方

- 開発用データでの判定は、**v0.5 の標準方式(今の製品)を、はっきり上回る**ことが条件です(詳細は [selection-rule.md](selection-rule.md))。
- 開発用データの結果は、候補を選ぶのに使うので、**独立した証拠ではありません**(選択による偏りがあります)。独立した確認は、最終評価(Gate C v3)でだけ行います。
- 最終評価の合格ラインは、これまでと同じ Gate B の凍結基準を、字義どおり当てはめます(関数 Top-1 0.4 以上、MRR 0.6 以上、現行との改善幅 +0.4 と +0.1、30件以上、3リポジトリ以上、p95 5秒以下、メモリ 8 GiB 以下、10億パラメータ以下)。基準は変えません。

## 守ること

- Gate C のデータ(使用済みの v2、準備中の v3)には一切触れません。
- データの中身(ケース、ラベル、ソース、ケース別の結果)は Git にも報告書にも載せません。集計値だけです。
- 外部のテスト実行は、この版では行いません(データは作成済みのものを使う)。
- 結果は MLflow に記録します。Discord の通知は使いません。
- 公開(Hugging Face、PyPI)と、バージョン番号の変更はしません。
