# v0.7 最終測定レポート(Gate C v4)

測定日: 2026-11-10 / 約束: [FROZEN-CANDIDATE.md](FROZEN-CANDIDATE.md)(測定前に固定、変更なし)

## 結論(3行)

1. 新しい評価データ(60ケース・5リポジトリ)で、凍結した候補 D(`stacktrace-callgraph-weighted`)は v0.5 標準より良い順位を出しました。Top-1 は 0.417 → 0.500(+0.083)、MRR は 0.512 → 0.591(+0.079)です。
2. 約束 F1(改善幅)・F2(後退なし)・F3(速さ)は達成。**F4(本体と評価用実装の順位が全ケース一致)は 58/60 で未達**です。約束の字義どおり、**「すべて満たした」とは言えません。**
3. 標準方式は v0.5 のままにします。標準にするかは、F4 の2件の食い違いの原因を調べたうえでオーナーが判断します(測り直しや定数の変更はしません)。

## 限界

- 評価データは「原因が必ず製品側のコードにある」合成データです。原因がテスト用の補助コードにある現場の失敗では、この方式は悪化します。
- 評価データの内訳は偏っています(原因がスタックの最も内側 22、深い位置 6、スタック外で呼び出し関係あり 6、関係なし 26)。pyparsing が全体の37%です。呼び出し関係の効果は、このデータではあまり試されていません。
- 改善は主に tomli(6件)に支えられ、件数が少ないため再現性は断定できません。
- F4 の2件の食い違いの原因は未調査です(本体と評価用実装の細かな差の可能性)。ケース別の中身は出していません。
- Gate C v4 はこれで使用済みです。再測定には新しいデータが必要です。公開・バージョン変更・push はしていません。MLflow には `v0.7.0-weighted-final-gatec-v4` として記録しました。
