# v0.5 独立確認の計画(測る前に固定)

作成日: 2026-11-10 / 状態: 測定前

## 目的

v0.5 の標準方式(スタック+呼び出し関係、AI モデルなし)が、**誰も結果を見ていない新しい評価データ(Gate C v3、60ケース・5リポジトリ)** でも、旧方式(スタック+語彙)より良いかを、**1回だけ**測って確かめます。v0.5 の開発用データでの結果は、選択の偏りがあり独立した証拠ではありませんでした。

## 測り方

- 比較する2つ: 旧方式 `baseline-stacktrace-lexical` と、標準の `baseline-stacktrace-callgraph`。重み・設定は v0.5 のまま。**調整しません。**
- 順位付けの対象は、リポジトリ全体の関数。旧方式は v0.4・v0.5 と同じ約束(旧方式が返した候補を先に、残りは ID 順)。
- 使うコード: `evaluation/run_callgraph_eval.py`(開発用データと同じ仕組み)。AI モデルは使いません。
- テストの実行はしません(失敗状態の木は作成済み)。報告は集計値のみで、ケース・正解・ログは出しません。

## 判定の約束(結果を見る前に固定)

| # | 内容 | 達成の条件 |
|---|------|-----------|
| C1 | 改善幅 | 関数 MRR の差(v0.5 − 旧方式)が +0.10 以上で、リポジトリ層別ブートストラップ(10,000回、乱数 20261030)の95%区間の下限が 0 より大きい |
| C2 | 偏りの確認 | リポジトリを1つ除いた5通りのどれでも、MRR の差が 0 より大きい |
| C3 | 速さ・軽さ | 索引づけ込みの処理時間 p95 が 5 秒以下、メモリ 8 GiB 以下 |
| C4 | Gate B の絶対基準(参考) | 関数 Top-1 ≥ 0.4 かつ MRR ≥ 0.6。満たさなくても v0.5 の標準は取り消しません(旧方式との比較が目的)。満たすかどうかを正直に書きます |

## 結果の扱い

- C1〜C3 をすべて満たす: 「独立データでも旧方式より良かった(60ケース、合成、小さなライブラリ)」と書く。
- C1 か C2 を満たさない: 標準を維持するか見直すかは、レポートに事実を書いてオーナー判断にします。結果を見て重みを変えて測り直しません。
- この結果で Gate C v3 は使用済みになります。再測定には新しいデータが必要です。
- 公開(Hugging Face、PyPI)やバージョン変更はしません。
