# v0.5 独立確認レポート(Gate C v3)

測定日: 2026-11-10 / 事前に固定した約束: [CONFIRMATION-PLAN.md](CONFIRMATION-PLAN.md)

## 結論(3行)

1. 誰も結果を見ていない新しい評価データ(60ケース・5リポジトリ)でも、v0.5 の標準方式は旧方式より順位が良くなりました(関数 MRR 0.358 → 0.458、差 +0.100)。
2. 事前に決めた約束 C1〜C3 はすべて達成です。ただし **Gate B の絶対基準(Top-1 ≥ 0.4、MRR ≥ 0.6)は満たしていません**(C4、参考)。
3. したがって言えるのは「旧方式より良い」までで、「十分な精度に達した」とは言えません。

## 点数(60ケース、リポジトリ全体から探す条件、AI モデルなし)

| 方法 | 関数 MRR | 関数 Top-1 |
|------|----------|-----------|
| 旧方式(スタック+語彙) | 0.358 | 0.283 |
| **v0.5 標準(スタック+呼び出し関係)** | **0.458** | 0.283 |

MRR は「正解がどれだけ上位に出たか」(1が最高)、Top-1 は「1位が正解だった割合」です。改善は2位以下の順位が上がったことによるもので、**1位の当たりは増えていません**。

## 約束との照合

| 約束 | 結果 | 判定 |
|------|------|------|
| C1 改善幅 +0.10 以上かつ区間の下限が 0 超 | +0.100(95%区間 +0.057〜+0.144) | 達成(基準ぎりぎり) |
| C2 1リポジトリ除いても差が正 | 5通りすべて +0.08〜+0.12 | 達成 |
| C3 p95 5 秒以下、8 GiB 以下 | p95 0.24 秒、0.10 GiB | 達成 |
| C4(参考)Top-1 ≥ 0.4 かつ MRR ≥ 0.6 | 0.283 / 0.458 | 未達 |

リポジトリごとの MRR(旧 → v0.5): pyflakes 0.331 → 0.393、markdown 0.455 → 0.499、h11 0.360 → 0.511、hpack 0.312 → 0.394、markupsafe(4件のみ)0.272 → 0.583。5つすべてで良くなっています。

## 限界

- 60ケースは小さなライブラリの1か所の変更を合成したもので、現場の失敗に当てはまるとは限りません。
- 改善幅の +0.100 は基準の境目で、ケース数も少ないため、再現性は断定できません。
- 評価データの約4割は「原因がスタックに出ない」ケースで、呼び出し関係なしでは見つけにくい設計です。Top-1 が伸びないのは、1位に来る関数の多くが依然としてスタックの内側の関数だからと考えられますが、ケース別の確認はしていません。
- この測定で Gate C v3 は使用済みです。再測定には新しいデータが必要です。
- 公開・バージョン変更はしていません。MLflow に記録しました(`v0.5.0-callgraph-baseline`、実行名 `v0.5-gatec-v3-confirmation`)。
