# v0.4 方法の選び方(結果を見る前に固定)

作成日: 2026-11-07 / 状態: **固定済み(実験前)**。計画は [PLAN.md](PLAN.md)。ここでは測る方法、設定の候補、選び方、止める基準を、点数を見る前に書きます。

## 評価の範囲

- データ: v0.3 の開発用データ(98ケース、4リポジトリ)。学習にも最終評価にも使っていません。最終評価データ(Gate C v2)は、この段階では使いません。
- 候補の範囲: 製品の索引づけ(`FailureLens.from_baseline().index`)が検出した、失敗状態のソースの**すべての関数とメソッド**。ケースごとに、その壊れたソースで作ります。
- 正解の判定: 既存の評価と同じ(正解の関数が上位に出るか。関数 Top-1 と MRR)。ケース別の結果は出力しません。

## 測る方法

| 記号 | 内容 |
|------|------|
| S0 | 同梱の baseline。返した候補の順が先、残りは候補IDの昇順 |
| L1 | 語彙の一致(全体)。**比較相手**。下記の BM25 |
| L0 | 語彙の一致(簡易)。参考。現行 baseline と同じ「エラーログの語が関数に何個含まれるか(上限3)」 |
| E-base | 基盤モデル CodeRankEmbed のそのまま。検索用の接頭辞なし |
| E-basepfx | 同、検索用の接頭辞あり(`Represent this query for searching relevant code: `) |
| E-v01 | v0.1 の重み(`506492b0…`) |
| E-v02b | v0.2 候補 b の重み(`b5405daf…`) |
| F-*(モデル, 重み) | 融合。下記の式 |

E-* は「エラーログ(`strip`)」と「各関数のソース」のコサイン類似度で並べます。関数は 512 トークンで切ります。

### L1(BM25)の定義

- 単語分割: 識別子を抜き出し、アンダースコアとキャメルケースで分けて小文字にし、3文字未満とストップワード(Python の予約語と、現行 baseline のストップワード)を除く。
- 文書: 候補の関数ソース。クエリ: エラーログ全文の単語の集合(重複は数えない)。
- 式: k1=1.2、b=0.75、idf=ln(1+(N−df+0.5)/(df+0.5))(N はそのケースの候補数)。同点は候補IDの昇順。

### 融合 F の式

`score = w_e·Ê + w_l·L̂ + w_s·s + w_g·g`

- Ê: そのケースの全候補でコサイン類似度を最小0・最大1に正規化。
- L̂: BM25 を最大値で割る(全部0なら0)。
- s: スタックの深さと例外発生箇所。ログの各フレームを、ファイル名の末尾一致と行番号で、最も狭い関数に対応させる。現行 baseline と同じ式 `(0.6·深さ + 0.2·最深フレーム) / 0.8`(深さ=(最大フレーム番号+1)/フレーム数)。フレームに対応しない関数は0。
- g: 呼び出し関係。各関数のソースから呼ばれている名前を AST で集め、同じ名前を持つ候補への辺(呼ぶ側/呼ばれる側の両方向)を張る。同名の候補が8個を超える名前は無視。スタックに出る関数(s>0)を起点に、辺をたどった最短距離 d が 1 なら 0.5、2 なら 0.25、それ以外は 0。起点自身は 0。
- 同点は候補IDの昇順。

### 設定の候補(固定)

- モデル: E-base、E-basepfx、E-v01、E-v02b の4種。
- 重み: w_e ∈ {0, 0.5, 1}、w_l ∈ {0, 0.5, 1}、w_s ∈ {0, 0.25, 0.5}、w_g ∈ {0, 0.25, 0.5}。すべて0の組は除く。80通り × 4モデル。
- これ以外の設定は、点数を見た後に追加しません。

## 選び方

1. 比較相手(S0、L0、L1)を除く、すべての方法(E-* と F-*)から、開発用データでの関数 MRR が最も高いものを「最良の方法」とする。
2. 同点は関数 Top-1。それも同点なら、0でない重みの数が少ない方、それも同点なら、重みの組の辞書順が小さい方。

## 止める基準(PLAN.md の再掲)

最良の方法の関数 MRR が L1 を **+0.05 以上** 上回り、かつ、対応のあるリポジトリ層別ブートストラップ(10,000回、乱数 20261030)の差の95%区間の**下限が0より大きい**こと。満たさなければ、この方向は止める。Gate C v2 には触れない。

## 補助の確認(判定には使わない)

- 設定の選択による楽観を見るため、「リポジトリ1つを除いて設定を選び、除いた1つで測る」(4回)を行い、全体の MRR を L1 と比べる。
- 候補の範囲に正解が含まれる割合(プール再現率)を、各方法の候補範囲ごとに報告する。
- 時間とメモリ: ケースごとに「索引づけ」「関数の埋め込み(キャッシュなし)」「順位付け」を分けて測る。最大の使用メモリ(RSS)も報告する。キャッシュありの値は別に示す。
- 手法は決定的(CPU、乱数なし)なので、3回の乱数試行は行わない。
