# Independent measurement runner (Issue #23)

`evaluation/independent_runner.py` is an evaluator-owned **library**, not an automatic Gate C execution. It has no model checkpoint or held-out path. CI uses synthetic fixtures only. There is no trained-model quality result or adoption decision in this change.

## Boundary and invocation

1. The evaluator loads local records with `load_private_cases(...)` from `evaluation/private_adapter.py`, supplying the exact record SHA-256, failing-state source manifest, approved train-repository manifest, and fixed `top_k`. Production validation requires at least 30 cases, 3 rights-cleared repositories, pinned failing snapshots, and no train/eval repository overlap. The evaluator separately verifies the manifest is complete and genuinely approved.
2. The evaluator calls `run_independent(cases, model_factory, model_spec=MethodSpec(...), metadata=...)`. `model_factory(seed)` creates a pinned scorer and returns a callable from the **unlabeled** `RankRequest` to a complete `RankResult`. The scorer must not retrieve its own pool. `None` for the factory means model **not run**, with N/A metrics and comparisons. No checkpoint is bundled or invoked by CI.
3. The baseline `supplied-pool-stack-lexical` scores only those supplied candidates with stack/path mentions and lexical source overlap. It is a shared-pool adapter, **not** a rerun of the shipped repository-retrieving baseline. The report compares with the best *actually run eligible* baseline; currently this single method. Adding other methods requires the same request contract and explicit method registration, not a claimed result.

The runner checks exact request digest, candidate permutation, `top_k`, and unchanged query/source bytes for each ranker on every case. Labels and repository strata remain evaluator-side. Ties use candidate ID ascending. Three seeds are fixed at `20261030`, `20261031`, `20261032`, with identical case order, candidate pool, `top_k`, and process. A model factory receives only the seed; no labels. Rankers must control their own random seeds. Model load is separately timed; inference latency is per-method, per-case wall time on warm loaded scorers. Its p95 is the linearly interpolated 95th percentile over cases. Process peak RSS (Linux KiB, macOS bytes converted to GiB) includes model load; it is process-high-water, not method-isolated. To make the resource comparison meaningful, use a fresh process and record CPU/GPU, software versions, model/data/code revisions, input SHA-256 digests, command, parameter count, and artifact bytes. Parameter count is a pinned model metadata assertion and must be independently verified against the checkpoint before real Gate C; it is not inferred from a fake ranker.

Function Top-1/MRR use **only** function-labeled cases; missing functions are N/A, not zero or file labels. File Top-1/Top-k and Recall@k are separate, over distinct ranked files. MRR uses the first relevant ranked function. The report contains sample counts and three-run min/median/max. For function Top-1/MRR it uses 10,000 repository-stratified paired case bootstrap resamples (seed `20261030`), sampling the same indices for baseline and model within each repository, and reports two-sided 95% percentile intervals for each method and model-minus-baseline. The first seeded run supplies one observation per case to bootstrap; reruns are not treated as independent cases. The frozen thresholds are Top-1 ≥0.4, MRR ≥0.6, absolute improvements ≥0.4 and ≥0.1, p95 ≤5 s, process peak ≤8 GiB, parameters ≤1B. Comparisons are mechanical booleans or N/A, **not** a Gate C decision.

The returned report contains aggregate counts, metrics, intervals, budgets, redacted miss-category counts, method/revision/digest metadata and no case records. For a model run, code/data/source-manifest/train-manifest/model digests, Python version, hardware token, and the fixed public command identifier `run_independent-api` are required; the evaluator retains any path-bearing invocation privately. Its metadata and method fields are allowlisted and rejected on unsafe syntax, but the evaluator must still review all values before committing. Private per-case details, labels, source, paths, and logs remain local and access-controlled; no private artifacts may enter Git, CI artifacts, or PR text. A future actual Gate C report is blocked until the checkpoint, rights/split provenance, and independent label quality are accepted. This runner does not certify any of those prerequisites.

## Issue #28 common-pool extension

The opt-in `evaluation/product_pool.py` adapter uses the shipped `FailureLens.from_baseline()` retrieval and passes its exact ordered pool to v3. See `docs/shipped-baseline-common-pool.md`. The default supplied-pool lexical comparator above remains a historical adapter, not the shipped comparator. Empty retrieved pools retain the original case denominator and count as misses for both methods; aggregate counts now include abstention and pool-recall diagnostics.
